# Fix: Raw IDs in Diff Output (removed/unchanged_refs)

## Problem Description

When `vsl_read_page` returns a diff with `removed` objects, the IDs are returned in raw format (e.g., `div_0_0_0_2_0_0_0`) instead of shortened format (e.g., `div_0`). This creates inconsistency:

- `added` objects → short IDs (e.g., `btn_0`, `div_1`) ✅
- `modified` objects → short IDs ✅
- `removed` objects → **raw IDs** (e.g., `div_0_0_0_2_0_0_0`) ❌
- `unchanged_refs` → **raw IDs** ❌

### Example Output (Problematic)

{
  "changes": {
    "added": [{"id": "btn_0", "t": "button", ...}],
    "modified": [{"id": "div_1", "p": [100, 200]}],
    "removed": [
      {"id": "div_0_0_0_2_0_0_0"},
      {"id": "button_0_0_0_2_0_0_0_0"},
      {"id": "span_0_0_0_2_0_0_1"}
    ],
    "unchanged_refs": []
  }
}
## Root Cause Analysis

### The Bug

The `reverseIdMap` in `ServerSession` is built **ONLY from the current document**:

// packages/mcp-server/src/session/serverSession.ts:111-118
if (doc.objects) {
  this.idMap = buildIdMap(doc.objects);
  this.reverseIdMap = buildReverseIdMap(doc.objects);
}
When a diff is generated, it contains:
- `removed` objects — IDs from `previousDocument` that no longer exist in `currentDocument`
- `unchanged_refs` — IDs that exist in both documents

The `reverseIdMap` only contains mappings for IDs present in `currentDocument.objects`. Therefore:
- Removed IDs (which existed in `previousDocument` but not in `currentDocument`) are **NOT in the map**
- The `replaceIdsInRemovedObject` function falls back to the raw ID:

// packages/mcp-server/src/utils/idMapper.ts:203-210
function replaceIdsInRemovedObject(
  obj: VslRemovedObject,
  reverseIdMap: Map<string, string>
): VslRemovedObject {
  return {
    id: reverseIdMap.get(obj.id) ?? obj.id  // ← fallback to raw ID
  };
}
### Why This Happens (Step by Step)

1. User opens page → `setSnapshot(doc1)` → `reverseIdMap` built from `doc1.objects`
2. Page changes (navigation, SPA update) → `setSnapshot(doc2)` → `reverseIdMap` rebuilt from `doc2.objects`
3. `getDiff()` compares `doc1` vs `doc2` → produces `removed` with IDs from `doc1`
4. `replaceIdsInDiff(diff, reverseIdMap)` → `reverseIdMap` only has `doc2` IDs
5. Removed IDs from `doc1` are not found → fallback to raw IDs

### Why `readable: true` is NOT the Cause

The `readable` parameter only affects HTML filtering (removing nav, footer, cookie banners). Both HTTP and render paths apply the same ID mapping logic:

// packages/mcp-server/src/tools/readPage.ts:206-208
const reverseIdMap = session.getReverseIdMap();
const finalSnapshot = replaceIdsInDocument(fullSnapshot, reverseIdMap);
const finalDiff = fullDiff ? replaceIdsInDiff(fullDiff, reverseIdMap) : fullDiff;
The issue is **not** about `readable` bypassing mapping — it's about the mapping being incomplete for diff operations.

## Proposed Fix

### Option A: Build reverseIdMap from Union of Both Documents (Recommended)

Modify `ServerSession.setSnapshot()` to include IDs from `previousDocument` when building `reverseIdMap`:

setSnapshot(doc: VslDocument): void {
  if (this.currentDocument) {
    this.previousDocument = this.currentDocument;
  }
  this.currentDocument = doc;
  this.version += 1;
  this.scrollContext = null;

  // Build ID maps from UNION of current + previous documents
  // This ensures removed/unchanged IDs from previous document are mapped
  if (doc.objects) {
    const allObjects = [...doc.objects];
    if (this.previousDocument?.objects) {
      allObjects.push(...this.previousDocument.objects);
    }
    this.idMap = buildIdMap(allObjects);
    this.reverseIdMap = buildReverseIdMap(allObjects);
  } else {
    this.idMap = new Map();
    this.reverseIdMap = new Map();
  }

  if (this.onSnapshotChange) {
    this.onSnapshotChange();
  }
}
**Pros:**
- Minimal code change
- Ensures all IDs (current + previous) are mapped
- Backward compatible

**Cons:**
- Slightly larger ID map (negligible for typical page sizes)

### Option B: Build reverseIdMap Lazily for Diff Operations

Modify `replaceIdsInDiff` to accept both current and previous documents:

export function replaceIdsInDiff(
  diff: VslDiff,
  currentDoc: VslDocument,
  previousDoc: VslDocument | null
): VslDiff {
  // Build combined reverse map
  const combinedObjects = [...currentDoc.objects];
  if (previousDoc?.objects) {
    combinedObjects.push(...previousDoc.objects);
  }
  const reverseIdMap = buildReverseIdMap(combinedObjects);
  // ... rest of implementation
}
**Pros:**
- Explicit about the requirement
- No changes to ServerSession

**Cons:**
- Requires changes at all call sites
- Rebuilds map on every diff operation

### Recommendation

**Option A** is preferred because:
1. Single point of change (ServerSession)
2. ID map is already cached and reused
3. Minimal risk of breaking existing functionality
